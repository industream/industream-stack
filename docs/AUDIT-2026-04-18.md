Date: 2026-04-18
Scope: `industream-swarm` + `industream-cli` repos
Trigger: fallout from the Postgres 18 PGDATA data-loss bug discovered during password-rotation testing (commit `42e4b64`). Audit run to identify similar latent issues.

## Executive summary

- **3 data-loss bugs** in the same class as the one already fixed. **1 fixed in this audit commit**, 2 require follow-up.
- **5 critical security issues** (shared-secrets across envs, password leakage via stdout, RW docker socket on a routable service, default `admin:industream` htpasswd, command injection via `--domain`).
- **7 high-severity reliability issues** including domain-change script using the wrong tool (`docker-compose` on a Swarm), init-only Postgres reconciliation, missing backups for MinIO / FlowMaker flows / ntfy, and zero rotation coverage for Grafana/Influx/MinIO/CloudBeaver admins.

Focused on things a malicious client or an ops mistake could exploit, and on latent traps that will bite under realistic conditions (upgrades, rotations, scale events). Skipped CVE scanning of dependencies and documented design choices (embedded Harbor community robot credential, self-signed TLS defaults).

## Remaining CRITICAL security issues

### 1. Secrets shared across `prod`/`dev`/`staging`

**File:** `scripts/setup/create-secrets.sh:150-173`
Docker secrets `prod_*`, `dev_*`, `staging_*` are written from the same base files in `secrets/`. A compromise of the weakest environment gives full prod access.

**Fix:** generate distinct random values per env; drop the `--env all` code path that writes a single value to three different secrets.

### 2. Passwords dumped to deploy stdout

**File:** `scripts/deploy-swarm.sh:1067-1100`
All admin passwords printed at the end of deploy. They end up in CI logs, tmux scrollback, `industream install` piped output.

**Fix:** gate behind `--show-credentials`; by default print the secret file path.

### 3. `worker-manager` has RW `/var/run/docker.sock` + Traefik route

**File:** `docker-stack.workers.yml:450`
The service is web-exposed at `workers.<domain>` and mounts the docker socket read-write. Any auth bypass or command-injection in that service grants root on the Swarm manager.

**Fix:** use `tecnativa/docker-socket-proxy` with minimum endpoints, or mount `:ro` + a strict auth middleware chain + rate-limit.

### 4. Default htpasswd `admin:industream` committed

**File:** `traefik-dynamic/traefik-dynamic.yml.template:63`
Protects the Traefik dashboard and the backup-monitor. Same default for every install.

**Fix:** generate per-install in `create-secrets.sh`, persist to a gitignored file, refuse start if the default-hash is detected.

### 5. Command injection via `industream install --domain`

**File:** `scripts/setup/seed-confighub.sh:122-148`
`$DOMAIN` is shell-interpolated into a `node -e` script run inside ConfigHub. A crafted domain can break out of the JS string literal and run arbitrary code in the container.

**Fix:** pass the domain via `docker exec -e DOMAIN=…` and read `process.env.DOMAIN` inside the JS.

## MEDIUM security / ops

- **Docker-socket-proxy unnecessarily `privileged: true`** — `docker-stack.traefik.yml:15`
- **No `cap_drop`, no `read_only`, no non-root `user:`** on any service — default containers run as UID 0 with full caps.
- **Secrets re-exported as env vars in `keycloak-entrypoint.sh:31-32`** — negates file-based isolation.
- **SQL injection in rotation scripts** (`rotate-postgres-password.sh:138`, `rotate-keycloak-password.sh`) — password with `'` breaks `ALTER USER ... PASSWORD '$NEW'`.
- **`PGPASSWORD` passed via env to `docker exec`** — password visible in `docker inspect` of the exec instance.
- **Unpinned `:latest` tags** on `grafana-industream`, `swarm-cronjob`, `tecnativa/docker-socket-proxy`, `flowmaker-worker-manager`, demo images.
- **CLI `npm install` at install time** (`install.sh:199`) — any malicious minor of `execa`/`jose`/`react` runs as root via `sudo npm link`. Should be `npm ci` with committed lockfile.
- **Greedy `sed` in uninstall** — `sed -i '/industream/Id' /etc/hosts` would remove unrelated lines mentioning "industream".
- **`X-Frame-Options` and CSP stripped** on `minio.<domain>` and `ironstream.<domain>` to allow iframe embedding — opens clickjacking. Use `frame-ancestors` allowlist instead.
- **`security-headers` middleware defined but never referenced** in `traefik-dynamic.yml.template:41` — HSTS/nosniff unused on user-facing routes.

## HIGH reliability

### 14. `change-domain.sh` uses `docker-compose` on a Swarm

**File:** `scripts/utils/change-domain.sh:87`
The script calls `docker-compose restart traefik uifusion` — no such tool effective on a Swarm deployment. Output suppressed with `|| true`. Result: domain updates in `.env` but Keycloak `--hostname`, Traefik `Host(...)` labels, Grafana `GF_SERVER_ROOT_URL`, UIFusion `UF_CONFIG_URL` all baked at deploy time → site 404s everywhere.

**Fix:** call `./scripts/deploy-swarm.sh --env <env>` at the end. Also regenerate certs, Traefik dynamic config, and UIFusion config (mirroring the `industream deploy` fix).

### 15. `init-postgres.sh` is a first-boot-only reconciler

**File:** `config/postgres-init/` + `docker-stack.yml:34`
Adding a new service to `POSTGRES_MULTIPLE_DATABASES` after the cluster is initialized never creates the DB or user. Rotated DB passwords in `secrets/` are never propagated to the live cluster.

**Fix:** turn `init-postgres.sh` into a reconciler — run it on every start via a custom entrypoint that waits for Postgres readiness then runs idempotent `CREATE USER IF NOT EXISTS`-style logic.

### 16. Missing backups

**File:** `scripts/backups/backup-volumes.sh:14,121`
Only Grafana is backed up. Not backed up: `minio-data`, `flowmaker-launcher-data`, `flowmaker-confighub-data` (LMDB — users' flow definitions!), `ntfy-data`, `alertmanager-data`, `cdn-server-storage`, `ironstream-postgres-data`.

**Fix:** extend coverage; add an invariant check that fails deploy if a declared volume isn't mapped to a backup job.

### 17. Rotation scripts missing for Grafana / Influx / MinIO / CloudBeaver / app DB users

`create-secrets.sh --regenerate` now correctly refuses to rotate secrets in use by a service (good). But the complementary rotation scripts only exist for Postgres and Keycloak admin. Everything else (Grafana admin, Influx admin+token, MinIO root, CloudBeaver, ironstream_db, timescaledb, databridge_pg, datacatalog_db, keycloak_db, grafana_db) has no safe rotation path.

**Fix:** add `rotate-grafana-admin-password.sh`, `rotate-influx-admin-password.sh`, `rotate-minio-root-password.sh`, and a generic `rotate-postgres-app-password.sh` for each app user (ALTER USER in DB → swap secret → update consumer service).

### 18. Keycloak realm imported once, never reconciled

**File:** `docker-stack.yml:82` (`--import-realm`) + `keycloak-realms/industream-realm.json`
`--import-realm` honors the JSON on first boot only. Edits to client configs, roles, identity providers are silently ignored on redeploy.

**Fix:** use `kcadm.sh` at deploy time to reconcile, or document that the JSON is bootstrap-only and ship a separate reconcile script.

### 19. Version-variable drift

- `POSTGRES_VERSION`: `17.4` (stack fallback), `18-alpine` (.env.example), `17.2` (README example).
- `INFLUXDB_VERSION`: `2.7` (backup fallback), `2.7.12` (data stack), `2.7.11` (.env.example).
- `ALERTMANAGER_VERSION`: `v0.28.1` (stack) vs `v0.26.0` (.env.example).

**Fix:** align fallbacks with `.env.example`, or drop fallbacks and fail-fast when the `.env` is missing.

### 20. `install.sh:134` — silent `git pull` failure

`git -C "$INSTALL_DIR" pull --ff-only 2>/dev/null || true` — same class as the `industream update` bug: diverged history, local modifications or auth failure silently skipped. Operator deploys stale repo thinking it's current.

## MEDIUM reliability

- **Restart policy `max_attempts: 0`** everywhere → crash loops hide bugs with no Swarm-level alert signal.
- **Postgres memory limit 256M** — tight on first boot (init-postgres.sh + Keycloak migrations + datacatalog schema). OOM during init = half-created users.
- **UIFusion / datacatalog-ui 64M limit** — tight for Nginx under load; TCP-only healthcheck hides 502s.
- **`databridge*` + Prometheus healthchecks = `NONE`** → Traefik routes to not-yet-ready services (502 on fresh deploys).
- **Keycloak `start_period: 90s`** too short on slow disks / cold DB. Raise to 300s.
- **`deploy-swarm.sh` relies on `cwd == PROJECT_DIR`** for relative bind mounts; `sed` post-processing of `docker-compose config` output is fragile under non-standard `$TMPDIR` or symlinks.
- **`backup-monitor` placement** not tied to the backup jobs' node — on multi-node Swarm, the monitor may see an empty local `backup-data` volume.
- **`swarm-cronjob:latest`** floating tag on the scheduler that owns all backups.
- **`minio_root_user` hardcoded to `admin`** across all installations in `create-secrets.sh:148` — only the password is actually secret.
- **`backup-postgres` image mismatch risk** — `postgres:${POSTGRES_VERSION:-17.4}` for `pg_dump`, different default from the running server.
- **`backup-influxdb` uses `INFLUXDB_ORG`** env but `.env.example` sets `INFLUX_ORG` (typo → wrong org at backup time).
